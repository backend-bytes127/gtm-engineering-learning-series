The brief

Marketing had collected leads from Google Ads, a conference, a LinkedIn lead form, a scraped LinkedIn export and two paid data providers (Apollo and ZoomInfo). Each file used different column names, date formats, phone formats and spellings. The task: merge everything into one contact list with the 11 columns on the template, following the Rules tab.

The Rules tab sets the standard for each field (for example, phones in E.164, titles spelled out, root domains only) and six merge rules. Two of them drive most of the work: the latest dated source wins for someone's employer and title, and ZoomInfo, then Apollo, then everything else wins for company facts.

Step 1

Map the columns

Every source calls the same thing something different: Work email, Email ID, Email Address, Email. The first node reads all seven sheets (the event workbook has two) and rewrites each row into one common shape. It also parses the four date formats, since the "latest source wins" rule needs them comparable:

  • Google Ads: 2026-10-12 13:09:15 IST
  • Event scans: 18/09/2026 13:25 (day first)
  • LinkedIn form: 10/04/2026, 01:48 AM (month first)
  • Scraped LinkedIn and Apollo: ISO timestamps. ZoomInfo has no dates at all.

Some mappings are deliberate choices. Phone numbers typed into the event booth notes (Mob 9542367611) are pulled out. ZoomInfo's Direct Phone is not read at all, and Apollo's Corporate Phone is ignored.

Step 2

Clean, and remove invalid records

Names lose salutations, credentials, pronouns, emoji and "Last, First" ordering. LinkedIn links are reduced to the public slug. Then nine rows are removed, and each one is logged with its reason on its own branch of the flow.

Step 3

Standardize to the Rules tab

This is where the Rules tab becomes code:

  • Company. Legal suffixes dropped, typos and short forms matched to the ZoomInfo or Apollo name (so "Zentrova" and "Kiranat Education" resolve correctly).
  • Title. Headline text removed and abbreviations expanded. "Dir. of Mktg", "Marketing Director" and "Director - Marketing" all become Director of Marketing.
  • Mobile. Converted to E.164 using the person's country. Fake numbers (1234567890), landlines (080-43057296) and numbers mangled by Excel (9.18772E+11) become blank.
  • Email. Lowercased, one address, generic mailboxes like info@ dropped, and placeholders like email_not_unlocked@domain.com rejected.
Step 4

Remove duplicates

Two records are the same person when they share an email, a LinkedIn slug, a Sales Navigator id or a mobile number. The same name and company counts only when the job title is compatible. A merge is refused if it would join two different LinkedIn slugs, which is why two people sharing the name "P. Nair" at the same company (a Marketing Manager and a CRO), and two sharing "R. Sharma" at different companies, stay separate.

The node also records every link it made, so each merge can be reviewed. Six people changed employers during the period; they appear once, at their latest employer.

Step 5

Enrich and merge

Each group becomes one row. Gaps are filled from other sources, and a cell stays blank when no source has the value:

  • Employer and title: the most recent dated record.
  • Website, HQ and size: ZoomInfo, then Apollo, then everything else. HQ is the company's, not the contact's city (one contact lives in Dubai but the employer's HQ city is shown).
  • Email: a work email on the current employer's domain first, a personal one only if nothing else exists.
  • Name: spelled the way the LinkedIn slug spells it ("Mohd" becomes "Mohammed" when the slug says so).
Step 6

Final output

The last Code node keeps exactly the 11 template columns, in template order. A Convert to File node turns the 90 rows into Final_Contact_List.xlsx, with the sheet named Final Output like the template.

Judgment calls, and how we decided them

Which phone is a mobile?

The Rules say mobile only. We tested each phone column against the numbers in the other files. Apollo "Corporate": 0 of 28 matched. ZoomInfo "Direct": 0 of 7. Both are board or direct lines, so they are excluded.

Apollo "Work Direct": 10 of 11 matched real mobiles elsewhere (it is a mislabeled mobile column), so it is accepted when another source agrees.

Same name, different person

Name alone is never enough. A shared name merges only with a second check, and never across two different LinkedIn identities.

That is why two names in the data each appear twice, with different titles or different employers.

People who changed jobs

Six contacts moved employers: three from PayNimbus to Orbexa, and one each from Northpeak to Harborline, Tarangi to Haldiya and Marinabay to Palmspire. Each shows their current employer, title and work email.

ZoomInfo has no dates, so it ranks lowest for this rule but still wins for company facts.

Blank beats a guess

Where no source has a value, the cell is empty: 30 mobiles, 8 LinkedIn URLs and 3 emails. The only email edits are two .con to .com typos, made only because the company domain is confirmed by ZoomInfo or Apollo.

Worth a human look

  • One contact (R.T.) is treated as a single person who moved from Cobaltrix to Silvertide. The records share a name and city but no email or LinkedIn link.
  • One contact (S.L.) has only an uncorroborated Apollo "Work Direct" value, so the mobile is blank.
  • "Purchase Manager" is treated as "Procurement Manager", and "Co-Founder & CTO" as "Chief Technology Officer".
  • Three contacts have only a personal email, and a few Apollo emails are marked "Extrapolated" (pattern guesses).

How we know it is right

We built the logic twice. First as a Python pipeline (68 automated tests, including a check of the whole output against every format rule on the Rules tab). Then we ported it to JavaScript for the n8n Code nodes, and ran the generated node code on the real files.

The first run inside n8n found two real problems the local tests had missed, listed below. After fixing them, the 90 rows from n8n matched the Python result exactly, and the downloaded xlsx was identical in content.

Problems we hit

Event Delegates returned 0 rows
In Extract From File, a range like A5 means the single cell A5. Fix: use the number 4 to skip the four title rows. The merge still produced 90 people, but nine rows had lost phones and emails, which only a row-by-row comparison caught.
A stray character after names with 🚀
n8n's spreadsheet reader turns 4-byte emoji into a private-use character. Fix: the cleaner strips that range as well.
The "Form ending" node redirected to a dead address
It redirects to WEBHOOK_URL, which in this environment pointed at an expired tunnel host. Fix: removed it; the file is downloaded from the run instead.
n8n could not read the project folder
The container only mounts its own data volume. Fix: the files come in through an upload form, the same pattern as the ICP form in project 1.
Seven event delegates had no company
Removing "no company" rows up front would have deleted real people. Fix: that check now runs after merging, when other sources have filled the gap.

Run it yourself

  1. Open http://localhost:5678/form/contact-merge-form-0001 (start Docker first if it is not running).
  2. Upload the six files from sample-data/ (or your own exports) and submit.
  3. In n8n, open the workflow's Executions tab and select the latest run.
  4. Open Convert to Final_Contact_List.xlsx and download the file.
